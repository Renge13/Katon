# Feed/Drain Lookup — all 20 MVP cells (DERIVED, cross-checked)

Fill `card.feed[]` / `card.drain[]` and beat-4's named types FROM THIS TABLE. Do not re-derive the
five-element cycle per cell — that is the #1 inversion error (Amplified is NOT fed by its feeder).
Derived from `bazi-states-and-compatibility-v4` and cross-checked against the canon base table, the
Matahari-Balanced reading's actual feed/drain, and the locked Hujan-Amplified "needs Wood outlet" spine.

## How to read it
- Names are listed as **Yang/Yin** pair for the element (e.g. Fire = Matahari/Pelita). On the card,
  pick the 1-2 names that best fit; you don't have to list both. Lead with the one a user is likeliest
  to recognize.
- **FEED** = "Yang Menenangkan" (moves the chart toward balance). **DRAIN** = "Yang Melelahkan" (worsens
  the imbalance). Card label string is fixed: YANG MENENANGKAN / YANG MELELAHKAN.
- The card array and beat-4 prose MUST name the same archetypes (the schema's dev-warning enforces this).

## The state logic (why the table looks like it does)
- **Balanced / Depleted** → base rule: FEED = feeder element; DRAIN = controller element.
- **Governed** (flooded by controller) → FEED = the element that controls the controller, + the feeder
  (absorbs the flood); DRAIN = more controller.
- **Amplified** (flooded by own element) → FEED = output + controller (both drain the excess); DRAIN =
  more of own element (echo chamber).
- **Over-fueled** (flooded by feeder) → FEED = output + what-D-controls (burn off the excess); DRAIN =
  more feeder.

## One caution for the author
Amplified rows list TWO feed elements (output + controller). On the CARD, pick the ONE that best fits
the archetype's story — usually the **output** element (the healthy outlet), since that's the
constructive "find your people" read. Reserve the controller-element feed for the paid beat-4 where you
have room to explain it. Don't crowd the card with all four names.
