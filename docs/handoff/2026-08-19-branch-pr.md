## This branch carries four unrelated bodies of work, and the name says so

none of the other eighteen. **Splitting 22 commits retroactively costs a day and buys
tidiness, so it was not done** (Reyner, 2026-08-19). An honest description of a mixed
branch beats a dishonest name on a clean one, and this section is that description.

— `/api/mirror/[token]` 404s without `MIRROR_PREVIEW_TOKEN` and is linked from
nowhere — so none of the four tracks needs to ship separately, and none is urgent.

## What is worth a reviewer's attention

**`npm run audit:card-contrast` exits 0 for the first time.** `FAIL - 8 finding(s)` →
`PASS`. Two `rendered` findings closed by removing the day cell's brass wash, four
`sheen` findings closed by measuring brass text against the surface it is actually
drawn on, and the remaining two excused as a named ruling with their ratios still
printed on every run.

**One exemption list stopped being empty, and that exposed a bug in the report.**
`SHEEN_EXEMPT` went from `[]` to `['乙','丙']`, and 乙 and 丙 immediately printed
`clears` in the very section that exists to keep their failure visible — because the
report row was recorded inside the `!exempt` branch. It is the same defect as
`21d690a`, one report over, and it was **untestable while the list was empty**. The
generalisation is in the ledger: an exemption mechanism cannot be tested until
something is put in it, so every sibling list has the same latent bug today.

**A ruling was made on a premise I got wrong, and the correction is in the code.**
The brass-text fallback was split per card on the stated grounds that pooling it
"made Card A pay for Card B's finish". Card A draws no brass text at all — all three
roles reading `brassText` are Card B only. The split is kept on a rebuilt argument
and changes not one pixel; a test pins Card A's zero-brass fact so the guard cannot
rot. Ledger row 39.

**Two gates both stamped `1.9.0` for a day.** The gate changes landed without the
bump, so the only thing separating them is file mtime. `render_cache` was read
before anything was ruled: zero rows under either, six rows at `1.8.0` under a
superseded `ENGINE_VERSION`, nothing served, nothing purged. Neither probe artifact
was re-stamped — the reconciliation is a PROGRESS row that says mtime is the evidence.

- **It does not promote the mirror.** Its four named preconditions are unchanged.
- **It does not set a retry depth.** The depth-6 sweep and the free erosion read are
  both in `docs/qa/`; depth stays at 1 until Reyner rules.
- **It does not close the rule-23 bracket hole.** `Aspek Pemikir (Indirect Resource)`
  → `Aspek Pemikir` passes the gate, and the bracket rate falls 99% → 82% → 66% by
  attempt number. Measured deliberately and not fixed: a coverage check changes what
  the gate rejects, so it needs its own measurement and its own version bump.
- **It does not touch the reader's wait**, which turns out not to exist yet: the
  funnel's 2.5s pause is a designed pause, not a wait on work, and the LLM path is
  fenced. The measured 7.6s p50 arrives at promotion, not before.
