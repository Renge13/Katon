## 5. Spec errors caught, with the pattern underneath

Candidate rows for the `COWORK-BRIEF.md` §4 ledger. Not appended — that file's rule is append-only
and attributing rows is Reyner's call, not mine.

**a. §6.4 asserted the outcome of the measurement it was ordering.** The section is headed *"Brass
on text must be measured, not assumed"* and then says `BRASS_TEXT` *"should clear 4.5 comfortably"*
on dark fields with Taman as the single risk. Measured: it failed on **five** of ten, three of them
dark fields. Pale brass is a *light* metallic, so the brightest fields cannot carry it — Bambu's
green and Matahari's orange fail alongside the light-field pair. *Pattern:* the disproving evidence
was one function call away, in the paragraph that commissioned the call.

**b. §6.5 framed a feasibility question as a magnitude question.** It asked whether the ceiling had
fallen — *"there may still be headroom, but the tripwire moves"*. The real answer was that **three
badges stopped fitting at all**, on real glossary copy that was inside the ceiling. A prompt that
asks "how much did X move" pre-commits the reader to X still existing.

**c. §6.8's table carried two hand-computed values that were wrong** (accent 7.19 for 7.18; old
brass 2.50 for 2.52). The section now says so itself. *Pattern:* hand arithmetic where the function
the tests read is one import away — the same discipline `CLAUDE.md` already demands for code facts.

**d. §2.6 contradicted itself.** Its opening said the watermark fill stays `accent` at the ruled
0.18/0.14; a later paragraph still argued that *"the alpha drop from the ruled 18% to 11.5% is what
actually lets the headline read over it"* and called it load-bearing. Fixed in the spec after
flagging.

**e. §3.5's predicate was inverted against its own examples.** *"Suppress the deboss when
`!inkIsDark(token)`"* — but the parenthetical named Taman, Permata and Embun, which are exactly the
tokens where `inkIsDark` is **true**, and the stated reason (a light field has no gradient for the
dark half to sink into) matches the names. Implemented to the names; fixed in the spec after
flagging.

**f. The 08-15 ruling froze a *displayed* value, not a measurement.** *"FREEZE THE FLOOR AT 3.31."*
3.31 is the two-decimal presentation of **3.3075**, rounded up, so freezing the literal put the bar
0.0025 above 丙 Matahari — the token that defines it — and the audit reported Matahari as failing
its own floor. The constant is now computed from the frozen source hexes; a test pins `toFixed(2)`
to `"3.31"`. *Pattern:* a number that appears in prose and in a comparison are not the same object.

**g. Minor:** §1 cross-references "§5.4", which does not exist. The intended target is §6.5.

**Two of these (d, e) were fixed in the spec inside the same cycle.** That loop worked.

### Environment gotchas that cost real time

- **Chromium taints a canvas drawn from any SVG containing `foreignObject`**, which is exactly how
  html-to-image renders. `toSvg` → blob → canvas is unreadable; only `toPng`'s output can be read
  back, because a PNG data URL does not taint.
- **`getImageData` needs a real origin.** From `file://`, or the preview pane's `data:` snapshot of
  one, the document is opaque and the read throws no matter what else is right.
- `toCanvas` stalls on a card-sized node; `toPng` returns in about 6 seconds. A 20s timeout looks
  like a hang.
- **A backtick inside a comment in a template literal breaks the script.** Hit twice, in two
  different generator scripts. Both times the error pointed at the line *after* the comment.

## 7. Open, and deliberately not closed

**The sheen costs contrast in the lit corner.** Card B's specular sheen is white-alpha over the
whole object, and on a light-ink token white moves the surface *toward* the ink — in the region the
headline occupies. Measured, ink over `composite(#fff, field, .15)`:
甲 5.96 · **乙 3.68** · **丙 3.61** · 丁 6.20 · 戊 6.34 · 庚 7.51 · 壬 6.71

Two locked tokens are under AA in that corner. The sheen is ruled at 0.15 and was **not** reduced —
scaling it per token would silently redesign the finish. It is reported in `audit:card-contrast` and
on the preview page. If it is to be fixed, the move is the field darkening that fixed Matahari on
08-13 and Gunung on 08-15. **This is the largest open item on the card.**

**己 Taman 3.26 and 癸 Embun 3.05 sit under the accent floor.** Both approved, both light fields,
both named in `ACCENT_EXEMPT`. Reyner has looked at them and left them.

**Neither card is wired to a route.** `grep -rn "CardA\|CardB" app/` returns nothing outside
`components/cards/`. Archivo is loaded now, so the trap §9 warned about is closed, but the cards
still reach no user.
